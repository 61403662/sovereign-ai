标题：主权 AI-10：混合问题的路由选择

摘要：价/BOM 强词优先于检验词；eval fan 第 6 题锁 route；尚非同答拼 RAG+SQL。

---

发表前脱敏：截图保留 [route: rag/sql] 与 26.7 等虚构数字即可；勿露完整本机路径。

开篇

从 AI-07 起，我们给 ask 定了一条好记的规则：要问价钱、BOM，就走 SQLite，终端会打 [route: sql]；要问检验、工艺、规格，就去翻你自己放进 data\raw 的文档，终端会打 [route: rag]。08 没动这条规矩，只是把 SQL 答案通过大语言模型加以自然语言润色；09 只是将本机 CSV 灌注到 BOM 库。从头到尾，都是 一句问题、一个入口。

可一线同事不会按「纯问价」或「纯问规章」来提问。他们常随口一问：「XF-120 检验时材料费多少钱？」——既有「检验」，又像在问 SOP；又有「材料费」，明明在要数。若系统一看「检验」就去翻文档，答出来的多是工艺段落，26.7 这种数就对不上账了。

AI-10 就解决这一小步：混合问题里，先分清你到底更想要「规矩」还是「数字」，让该走 SQL 的别误走文档。文末也会说清楚：现在还做不到一句里同时给你 SOP 引用和材料费合计，那是下一篇的事。

---

一、AI-07 的简化经验不够用了

【图1】

07 跟做时有一句好记的经验：出现检验、工艺、计划等，倾向走 RAG。对纯文档题，这没问题，例如：

· 每批尺寸抽检至少几件？ → rag

· 扇叶划痕能否让步接收？ → rag

· XF-120 装配工艺螺栓扭矩多少？ → rag（扭矩应在工艺 md 里，不在价表里）

可一旦问句里同时出现「检验」和「材料费、多少钱、BOM」这类询价词，就要升级规则：先判断你是不是在要钱、要清单，再决定要不要被「检验」拽回文档。

原则不变：数字仍以 SQLite 为准；变的是路由优先级，不是 SQL 怎么算。

---

二、混合问题：怎么知道走 SQL 还是走文档？

【图2】

不用背源码。跟做时看终端第一行 [route: rag] 或 [route: sql] 就够了。可以记成大白话：

· BOM 库还没灌好 → 不会硬查价，该走文档的仍走文档。

· 整句只是在问规章、工艺、检验 → 走文档（翻 data\raw）。

· 句子里只要冒出「材料费、多少钱、BOM、有哪些料、型号、样例库」这类 **要钱、要清单** 的词 → **走 SQL 查库**，就算句子里还带着「检验、工艺、计划」也不改。

· 没有在要钱，却在问检验、工艺、规范、装配 → 走文档。

· 其余一眼就是「列物料、估材料费、哪家便宜」→ 走 SQL。

这一句要记住：**一次只选一条路。** 不会在同一条回答里，又给你 SOP 引用，又给你 26.7 合计——那是后面「复合答」要干的，不是 AI-10。

三句话照抄自测（建议截图）：

· XF-120检验时材料费多少钱？ → 应看到 [route: sql]，有 26.7（检验和材料费同句，**以要钱为准**）。

· XF-120 装配工艺螺栓扭矩多少？ → 应看到 [route: rag]（问工艺，查文档）。

· 每批尺寸抽检至少几件？ → 应看到 [route: rag]，能答出至少 5 件之类（纯规章，与 BOM 无关）。

三、怎么验收？eval 里有一道题专查「走错路」

【图3】

仓库里的 fan 回归集（eval/fan_qa.example.jsonl）第 6 行，就是上一节那句混合提问：XF-120检验时材料费多少钱？ 它要求两件事：终端标成 [route: sql]，答案里要有 26.7。

你跑 .\scripts\eval-all.cmd 时，不只对数字，还对「路有没有走对」。走成 rag 了，这一题会直接报 FAIL，比肉眼扫一眼靠谱。

整套仍是 7 道文档题 + 6 道 BOM 题，最后一行应是 total 13/13。以后改过路由或 BOM 相关代码，记得两组一起跑。

五、别和「复合答」混在一起

【图5】

有人会问：扇叶划痕能否让步？同时 XF-120 材料费多少？

当前版本（写到 10 为止）：一次 ask 只选一条路——要么整段 RAG，要么整段 SQL，不会在同一次回答里拼「SOP 引用 + 26.7」。

那叫复合答，要等后面篇章（拆意图、两路各跑、合并版式与 eval）。10 只保证：混合句别走错路。

---

六、排障（每条一行）

· 混合句走了 rag 且数字像瞎编 → 是否含材料费/多少钱；git pull；库是否 ready。

· 纯工艺题误走 sql → 是否误夹 BOM 强词；改说法或后续收紧分类。

· fan L6 FAIL → route 不是 sql，或没有 26.7。

· eval 过、手测 route 反了 → 确认都用 ask.cmd / 同一 ask_question 入口。

---

七、边界（心里有数就行）

· 走哪条路，是靠问句里有没有「材料费、多少钱」这类 **写死的词** 来判断的，不是把整句话丢给云端大模型去「猜你要啥」。

· 同事换了一种口语说法，系统可能认不出来——要在代码里 **补关键词**，在 eval 里 **加一道例题**，才算真支持。

· 现在还 **不支持聊天上下文**：你上一句问了啥，下一句不会自动带着；**每一句单独判一次** sql 还是 rag。

· **材料费、BOM 合计** 一律来自本机 SQLite；大模型只负责把已经算好的数 **念顺**，不会去 **估算价钱**。
