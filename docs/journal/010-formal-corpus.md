# 主权 AI-10：混合问题的路由选择

> Phase 2 全貌见 **`docs/PHASE2-ROADMAP.md`**。本篇对应 **支柱 B（统一路由）** 的进阶：**一句里既有文档词又有询价词** 时怎么选路；**不是** 一篇里同时输出 RAG+SQL 两段答案（支柱 I，留给 11+）。

发表前脱敏：截图保留 `[route: …]` 与 **26.7** 等虚构数字即可；勿露内网路径全名。

## 开篇

从 **AI-07** 起，给 **`ask`** 定了一条好记的规则：**问价钱、BOM → SQLite**，终端 **`[route: sql]`**；**问检验、工艺、规格 → `data\raw` 文档**，终端 **`[route: rag]`**。**08** 没动这条规矩，只是把 SQL 答案通过大语言模型加以自然语言润色；**09** 只是将本机 CSV 灌注到 BOM 库。从头到尾，都是 **一句问题、一个入口**。

一线很少按「纯问价」或「纯问规章」提问，常随口：**「XF-120 检验时材料费多少钱？」**——既有「检验」又像 SOP，又有「材料费」明明要数。若一见「检验」就 RAG，答的是工艺段，**26.7** 对不上账（fan eval **L6** 专钉此句）。

**本篇**：混合问题里 **价/BOM 优先于文档词** 怎么选路；**手测 + eval-all 13/13**；**边界**：尚非同答拼「SOP 引用 + 材料费」（见 11+）。

---

## 一、问题从哪来：07 的简化表不够用了

【图1】

07 手测表里有一句经验：**出现检验、工艺、计划等 → 倾向 RAG**。对 **纯文档题** 成立，例如：

- 每批尺寸抽检至少几件？ → **rag**  
- 扇叶划痕能否让步接收？ → **rag**  
- XF-120 装配工艺螺栓扭矩多少？ → **rag**（工艺在 md，不在 BOM 价表）

但一旦 **询价词** 和 **检验词** 同句出现，规则要升级：**先认「是不是在要钱/要 BOM」**，再决定要不要被「检验」拽回文档。

原则不变：**数字仍以 SQLite 为准**；变的是 **路由优先级**，不是 SQL 算法。

## 二、混合问题：怎么知道走 SQL 还是走文档？

【图2】

实现见 `sovereign_ai/ask/route.py`（BOM 意图在 `bom/router.py`）。读者侧不必背模块名，**看终端 `[route: …]`** 即可。大白话版：

1. **库未就绪** → 不硬走 SQL。  
2. **纯规章/工艺/检验** → **RAG**（`data\raw`）。  
3. 句里有 **材料费、多少钱、BOM、有哪些料、型号、样例库** 等 **要钱/要清单** → **SQL**，即便同句还有检验、工艺、SOP。  
4. 没有在要钱，却有检验、工艺、规范、装配等 → **RAG**。  
5. 列料、估本、比供应商 → **SQL**。

**一次只选一条路**——不同答里同时拼 SOP 引用 + 材料费（支柱 I，非本篇）。

**三句照抄手测：**

| 问题 | 预期 |
|------|------|
| XF-120检验时材料费多少钱？ | sql，26.7；**以要钱为准** |
| XF-120 装配工艺螺栓扭矩多少？ | rag |
| 每批尺寸抽检至少几件？ | rag |

## 三、怎么验收？`eval-all` 里有一道题专查「走错路」

【图3】

`eval/fan_qa.example.jsonl` **第 6 行** 钉混合句（`XF-120检验时材料费多少钱？`）：须 **`route: sql`** 且答案含 **26.7**。

`eval-all.cmd` **同时对数字和 route 判分**；误走 RAG → **FAIL**。全量 **7+6=13/13**；动过 `route.py` 或 BOM 分类 → **RAG 与 fan 两组都跑**。

## 五、和「复合答」的区别（支柱 I，尚未做）

【图5】

读者有时会问：

> 扇叶划痕能否让步？同时 XF-120 材料费多少？

**当前（10 篇当下）**：`ask_question()` **只选一条路**——要么 RAG 一整段，要么 SQL 一整段，**不会**在同一次响应里拼 **「引用 SOP 第 x 条 + 材料费 26.7」**。

那叫 **复合答 / 混合输出**（路线图 **支柱 I**），需要：

- 意图拆句或子问；  
- 两路各跑一遍；  
- 合并版式与 eval 用例。

**10 只解决「别走错路」**；**11 及以后** 再谈 **「两路都答」** 或 **UI 里看清 intent**。

## 六、排障

| 现象 | 优先查 |
|------|--------|
| 混合句走了 rag，数字胡说 | 是否含 **材料费/多少钱**；`git pull` 是否含混合路由；库是否 ready |
| 工艺题误走 sql | 是否误含 BOM 强词；调整说法或后续收紧分类 |
| fan L6 FAIL | `route` 不是 sql，或答案无 **26.7** |
| eval 过、日常问 route 反了 | eval 走统一 `ask_question`；确认与手测同一入口 |

---

## 七、边界说明

- **选路**靠问句里的 **关键词表**（材料费、多少钱、BOM…），**不用**云端 LLM「猜意图」。  
- **新口语** → 补词 + 补 eval 用例，才算支持。  
- **无多轮**：每问 **独立** 判一次 route。  
- **材料费** 只来自 SQLite；模型 **只润色、不算账**（见 08）。
