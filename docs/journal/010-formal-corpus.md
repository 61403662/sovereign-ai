# 主权 AI-10：混合句怎么路由——检验里出现「材料费」仍走 SQL

> Phase 2 全貌见 **`docs/PHASE2-ROADMAP.md`**。本篇对应 **支柱 B（统一路由）** 的进阶：**一句里既有文档词又有询价词** 时怎么选路；**不是** 一篇里同时输出 RAG+SQL 两段答案（支柱 I，留给 11+）。

发表前脱敏：截图保留 `[route: …]` 与 **26.7** 等虚构数字即可；勿露内网路径全名。

## 开篇

**07** 立了规矩：**算钱的走库，讲规矩的走文档**，终端先打 **`[route: rag]` / `[route: sql]`**。  
**08** 只改「怎么说」，不改口径；**09** 只改「库从哪进货」，仍是一条 `ask`。

现场问法很少干净。常见：

> **XF-120 检验时材料费多少钱？**

句子里有 **「检验」**（像文档/SOP），又有 **「材料费」**（像 BOM/SQL）。若机械地「见检验就走 RAG」，会得到工艺段落，**对不上账**——这也是 fan 回归 **第 6 题** 要钉死的原因。

**这一篇讲清三件事：**

1. 当前 **混合句路由规则**（价/BOM 强词优先于文档词）。  
2. **怎么手测 + `eval-all` 验收**（含 L6）。  
3. **诚实边界**：仍是 **一条路二选一**，尚未 **同答里拼「SOP 引用 + 材料费数字」**（下一阶段）。

---

## 一、问题从哪来：07 的简化表不够用了

【图1】

07 手测表里有一句经验：**出现检验、工艺、计划等 → 倾向 RAG**。对 **纯文档题** 成立，例如：

- 每批尺寸抽检至少几件？ → **rag**  
- 扇叶划痕能否让步接收？ → **rag**  
- XF-120 装配工艺螺栓扭矩多少？ → **rag**（工艺在 md，不在 BOM 价表）

但一旦 **询价词** 和 **检验词** 同句出现，规则要升级：**先认「是不是在要钱/要 BOM」**，再决定要不要被「检验」拽回文档。

原则不变：**数字仍以 SQLite 为准**；变的是 **路由优先级**，不是 SQL 算法。

## 二、现行规则（不必背代码，跟做看现象）

【图2】

实现集中在 `sovereign_ai/ask/route.py`（BOM 意图仍在 `sovereign_ai/bom/router.py`）。逻辑可压成四步：

1. **库未就绪**（无 `fan_bom.db`）→ 不问 SQL，BOM 类会回落或提示先 import。  
2. **`classify_bom_question` 为 UNKNOWN** → 不走 SQL（纯文档题在此结束）。  
3. 问句含 **价/BOM 强词**（如 **材料费、多少钱、BOM、型号、样例库** 等）→ **走 SQL**，即便同时含 **检验、工艺、SOP、计划** 等文档词。  
4. 否则若含 **文档强词**（检验、让步、工艺、规范、装配…）→ **走 RAG**。  
5. 其余已识别的 BOM 意图（列料、估本、比供应商）→ **走 SQL**。

**混合句金标准（建议照抄手测）：**

| 问题 | 预期 route | 要点 |
|------|------------|------|
| XF-120检验时材料费多少钱？ | sql | 含检验 + 材料费 → **价赢** |
| 做一台 XF-120 材料费多少钱？ | sql | 纯询价 |
| XF-120 装配工艺螺栓扭矩多少？ | rag | 工艺在文档 |
| 每批尺寸抽检至少几件？ | rag | 无 BOM 意图 |

## 三、`eval-all` 里的钉子：fan 第 6 题

【图3】

`eval/fan_qa.example.jsonl` 第 6 行：

```json
{"question": "XF-120检验时材料费多少钱？", "route": "sql", "expected_contains": ["26.7"]}
```

跑 `eval-all.cmd` 时不仅看答案里有没有 **26.7**，还会校验 **`route` 是否为 sql**。  
因此：**路由错了会直接 FAIL**，比肉眼扫一眼更狠。

全量回归仍是 **7 题 RAG + 6 题 fan = 13/13**。改 `route.py` 或 BOM 分类后，**两组都要跑**。

## 五、和「复合答」的区别（支柱 I，尚未做）

【图5】

读者有时会问：

> 扇叶划痕能否让步？同时 XF-120 材料费多少？

**当前（10 篇当下）**：`ask_question()` **只选一条路**——要么 RAG 一整段，要么 SQL 一整段，**不会**在同一次响应里拼 **「引用 SOP 第 x 条 + 材料费 26.7」**。

那叫 **复合答 / 混合输出**（路线图 **支柱 I**），需要：

- 意图拆句或子问；  
- 两路各跑一遍；  
- 合并版式与 eval 用例。

**10 只解决「别走错路」**；**11 及以后** 再谈 **「两路都答」** 或 **UI 里看清 intent**。

## 六、排障

| 现象 | 优先查 |
|------|--------|
| 混合句走了 rag，数字胡说 | 是否含 **材料费/多少钱**；`git pull` 是否含混合路由；库是否 ready |
| 工艺题误走 sql | 是否误含 BOM 强词；调整说法或后续收紧分类 |
| fan L6 FAIL | `route` 不是 sql，或答案无 **26.7** |
| eval 过、日常问 route 反了 | eval 走统一 `ask_question`；确认与手测同一入口 |
